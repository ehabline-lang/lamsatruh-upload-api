# خدمة رفع صور لمسة روح — تحديث الحماية 2026-10-19

هذه ملفات خدمة `ehabline-lang/lamsatruh-upload-api` الخاصة بـ Vercel. تم تطويرها من ZIP المستخدم، والموقع على Firebase لا يحتاج تغييراً لاستعمالها. لم يتم تعديل GitHub أو نشر الخدمة أو تجربة مفاتيح المستخدم.

## قبل التركيب
احتفظ بالمستودع القديم وإعدادات Vercel الحالية. لا تضع كلمات مرور أو مفاتيح Bunny في GitHub. لا تستبدل قيم المتغيرات الحالية بالقيم التوضيحية في `.env.example`.

## التركيب خطوة بخطوة
1. في مشروع Vercel نفسه، افتح Settings → Environment Variables. أضف المتغير غير السري `FIREBASE_PROJECT_ID` وقيمته `project-30bd6827-dbde-4eff-b0a` إذا كان هو مشروع Firebase الحالي. تمت قراءة هذا المعرف من `.firebaserc` بمجلد الموقع على E، وليس من مفتاح سري. تأكد من تطابقه مع مشروعك قبل النشر. أضفه للبيئة Production ولأي Preview تريد اختباره.
2. أبقِ `FIREBASE_API_KEY` و`BUNNY_STORAGE_ENDPOINT` و`BUNNY_API_KEY` و`BUNNY_CDN_URL` على قيمها الحالية. متغيرا `ADMIN_EMAIL` و`UPLOAD_SECRET` القديمان لا يستعملهما هذا الكود؛ يمكن تركهما ولا تحتاج كشفهما أو إضافتهما إلى الموقع.
3. الدومينان `https://lamsatruh.com` و`https://www.lamsatruh.com` مسموحان. إذا تستعمل نطاق Firebase Hosting أو تشغيل الموقع المحلي، أضف `ALLOWED_ORIGINS` وفيه الروابط الدقيقة مفصولة بفاصلة، مثلاً `http://localhost:5173,http://127.0.0.1:5173`. بدون شرطة مائلة بالنهاية. لا تضف روابط غير موثوقة.
4. فك ZIP، واستبدل `api/upload.js` و`package.json` في مستودع GitHub بنفس الملفات المرفقة، وأضف مجلد `lib` و`package-lock.json` و`.gitignore` وبقية الملفات. احتفظ بالمجلدات كما هي؛ ملف `api/upload.js` يحتاج `lib/security.js`.
5. انتبه: حفظ الملفات في فرع الإنتاج المرتبط بـ Vercel قد ينشر التحديث مباشرة. الأفضل تجهيز كل الملفات في فرع واحد ثم دمج التغيير بعد مراجعة الإعدادات، حتى لا يُنشر ملف الرفع وحده قبل إضافة مكتبته.
6. الخدمة تحتاج Node.js 22 أو أحدث؛ Node.js 24 مناسب. التثبيت يثبت مكتبات `firebase-admin` و`sharp` و`formidable` من ملف القفل. لا تحتاج ملف service-account ولا مفاتيح Firebase Admin خاصة ولا Firebase Functions أو تغيير خطة Firebase.
7. بعد نجاح نشر Vercel، سجل خروج من لوحة الموقع ثم ادخل بالبريد وكلمة المرور ورمز Google Authenticator. جرّب صورة رئيسية وثانية مع علامة مائية، ثم مستخدماً لا يملك صلاحية الرفع. هذه التجربة الحية لم ينفذها الوكيل.

## التغييرات
- التحقق من توقيع Firebase ID token ومشروعه وانتهائه عبر Admin SDK، ثم البريد الموثق وTOTP، وحالة حساب Auth الحالية ووقت إلغاء الجلسات عبر accounts:lookup.
- قراءة ملف `users/{uid}` عبر Firestore REST باستعمال رمز الموظف نفسه. لا صلاحيات Admin تتجاوز القواعد. يلزم active=true ودور admin/manager/products أو صلاحية media.upload الصريحة. حذف الملف أو تعطيله أو إزالة الصلاحية يوقف الرفع بالطلب التالي. الاعتماد على تطابق البريد وحده أزيل.
- صورة واحدة فقط في حقل `file`، بحد 4 MiB للملف وحد لطلب multipart، وفحص الامتداد ونوع الصورة وفك محتواها فعلياً بمكتبة sharp. JPG/PNG/WEBP فقط، أبعاد أقصاها 8192 لكل ضلع و16,777,216 بكسل، بدون صور متحركة. الناتج JPEG بامتداد صحيح واسم UUID، وتُحذف metadata والمحتويات الإضافية عند إعادة الترميز. العلامة المائية المدمجة بالبكسلات تبقى؛ شفافية PNG تُسطح على الأبيض.
- يحافظ الرد على `{success,url,path}` والمسار `/api/upload` والملف داخل `products/`؛ لا تغيير مطلوب في uploadService.js بالموقع. إعادة الترميز قد تغير حجم الملف وجودة الضغط قليلاً.
- تنظيف ملفات الطلب المؤقتة بعد النجاح والرفض، ومهلة للاتصالات الخارجية، وعدم متابعة التحويلات، ورسائل خطأ عامة لا تكشف رد Bunny أو المسارات الداخلية.
- CORS بالروابط الدقيقة، ورؤوس no-store وnosniff، وإصلاح وضع إعداد bodyParser بعد تصدير الدالة حتى لا يضيع.
- حد 5 طلبات لكل مستخدم في الدقيقة **لكل نسخة تشغيل فقط**، بذاكرة محدودة. هذا ليس حداً موزعاً بين خوادم Vercel ولا بديلاً عن WAF/مخزن مشترك. الطلبات بدون Origin تبقى بحاجة إلى الرمز والصلاحية؛ CORS وحده ليس حماية دخول.

## التحقق المحلي وحدوده
نفّذ `npm ci` ثم `npm test` و`npm run check`. الاختبارات تستخدم HTTP وmultipart وصور JPG/PNG/WEBP حقيقية، والتحقق من محتوى الملفات وتنظيف المؤقتات؛ اتصالات Firebase/Bunny الناجحة محاكاة ولا تستعمل بيانات المستخدم. Admin SDK الحقيقي اختُبر ضد الرموز التالفة وغير الموقعة. نجاح التحقق برمز موظف حي والنشر الفعلي يتأكد بعد تركيب المستخدم. `npm audit --omit=dev` أعاد صفراً من الثغرات المعروفة وقت الفحص، وهذا ليس ضماناً للمستقبل.

Vercel يحد جسم الطلب إلى 4.5 MB، لذلك حد الصورة هنا 4 MiB مع مساحة لـmultipart، وليس 5 MiB كما في الملف القديم. عند 413 اختر صورة أصغر. المراجع: https://vercel.com/docs/functions/limitations ، https://firebase.google.com/docs/auth/admin/verify-id-tokens ، https://sharp.pixelplumbing.com/api-constructor/ .
